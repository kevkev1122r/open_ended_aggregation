*Condensed for #general. Full detail in `docs/handoffs/HANDOFF_2026-08-20.md`.

---

**Two results today, one good, one that changes the story.**

**1. Found a weighting mechanism that actually beats the ceiling.** On QAMPARI at
n=8, *every* rule that reweights the support pattern is null — I showed last time
that the best possible such rule (`pattern`, a lookup of P(correct | exactly
these agents assert)) only gets +0.25 over plain counting, ns. That bounds
correlation-aware and omission-aware weighting too, since the pattern already
encodes who agreed and who was silent.

So the only way up is to condition on something outside the pattern. Two things
were sitting in the cached data for free:

- **rank** — QAMPARI answers are ordered lists, and precision falls hard with
  position: 29% at rank 1, 16% at rank 11, 6% at rank 26.
- **verbosity** — items from an agent that listed 5–9 of them are 34% correct;
  from an agent that listed 50+, 1.9%. Kimi's median list is 13 items, its
  longest is 2431. One global weight reports the same number for both.

Adding rank: **30.52 vs 29.35 for counting (+1.16), and +0.92 over the pattern
ceiling — both significant.** First arm in the project to clear it.

Two controls, because this is the kind of result that's usually an artifact:
- truncating the *best single agent's* list gets 28.89 — worse than counting. So
  it isn't "short lists win under F1"; the ensemble is doing the work.
- a two-integer rule (keep if ≥θ agents assert AND min rank < R) gets +0.63.
  Half the gain is available from something you can state in one line.

Also tested the diversity/error-correlation idea (down-weight agents that
hallucinate together): **λ = 0 selected in all 5 folds, no gain.** Expected in
hindsight — it's a function of the support pattern, so the ceiling already caps
it. Question-domain weights (QAMPARI has 5 question sources) also: +0.00.

**Caveat, and it's a real one:** on ASQA the same rank arm lands 0.90 *below* the
ceiling. Either position-in-a-list is a genuinely different signal from
position-in-a-paragraph, or my fitting label is wrong there (it's recall-flavoured
while DR penalises length — ASQA's rank arm has the best STR-EM and the worst
ROUGE-L, which is what that failure looks like). Free to re-run; doing it next.
Until then the rank claim is for enumerative answer formats only.

**2. The ensemble-size crossover does NOT replicate on ASQA. It reverses.**

```
        QAMPARI (8 agents, F1)      ASQA (6 agents, DR*)
 size    count  weighted  diff      count  weighted  diff
   3     22.15    24.40  +2.25      25.88    26.71  +0.83
   4     23.69    25.59  +1.90      25.30    26.74  +1.44
   5     26.17    26.56  +0.40      24.70    26.90  +2.19
   6     27.74    27.38  -0.36      24.27    27.01  +2.74
```

Clean monotone trends in opposite directions. So "weighting matters at small
ensembles and count becomes a sufficient statistic by n=6" is a **QAMPARI fact,
not a general one** — I had it as the headline and it doesn't survive contact
with a second dataset.

And on QAMPARI itself, the crossover turns out to be a property of *support-
pattern* rules specifically. Ran all 210 ensembles with the rank arm added
(gain over counting):

```
 size   weighted   pattern(ceiling)   rank        rank sig.
   3      +2.25         +2.73        +4.12         56/56
   4      +1.90         +2.57        +4.16         70/70
   5      +0.40         +1.13        +2.74         50/56
   6      -0.36         +0.36        +1.86         21/28
  (8)     -1.25         +0.25        +1.16
```

Everything decays — so the 18 Aug mechanism is still right — but **rank stays
significantly ahead at every size**, including where weighting has gone negative
and the ceiling is null. Pattern-based weighting crosses over around n≈5–6; rank
doesn't cross over anywhere we can measure. (The count / weighted / pattern
columns reproduce the earlier runs exactly, so this is two independent harnesses
agreeing.)

Also: **on ASQA, counting never beats the best single agent — 0 of 42
ensembles**, and falls further behind as the pool grows (−0.70 → −2.26). MA-count
is the arm we're proposing as the contribution, so we should say this ourselves
rather than let a reviewer find it.

**3. What actually predicts the direction — and it's one number.**

```
                      P(correct|1 agent)  P(correct|>=2)   ratio
  QAMPARI                    1.2%             19.9%        0.06
  ASQA                      22.5%             47.5%        0.47
```

Both benchmarks are ~87% solo candidates, so the solo *share* tells you nothing.
What differs is what a solo claim **means**. On QAMPARI it's 16× less likely to
be right than a supported one, so a count threshold is already a near-perfect
filter — and it sharpens as the pool grows. On ASQA a solo cluster is only 2×
worse, so counting throws away most of the content for almost no precision, and
the only thing left to filter on is *who* said it — which gets more valuable with
more agents.

**Proposal: run `solo ratio = P(correct | k=1) / P(correct | k≥2)` as a screen on
any candidate dataset before implementing anything for it.** Costs one pass over
cached generations. Low (≲0.15) → counting wins, weighting is redundant. High
(≳0.4) → weighting is necessary. @Vihan this is probably the fastest filter for
the third-dataset search — it tells you up front whether a dataset can adjudicate
our question, which is exactly the trap QUEST and STR-EM-scored ASQA both fell
into.

One thing worth flagging because we predicted the opposite: **pool heterogeneity
does not explain this.** ASQA's pool is far *more* homogeneous (CV 0.125 vs
QAMPARI's 0.439) and it's where weighting wins biggest. Dominance still predicts
the gain *within* QAMPARI (r = +0.49), but on ASQA that correlation is only
+0.11. So it's a within-benchmark modifier, not the separator.
