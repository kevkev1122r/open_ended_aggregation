## 1. Rank-aware aggregation breaks the pattern ceiling

`analysis/beyond_pattern.py` — QAMPARI, 777 q, 8 agents, 5-fold cross-fitted,
zero API calls.

```
  arm                  F1               vs count     vs pattern ceiling
  ---------------------------------------------------------------------
  count             29.35            (reference)  -0.25 [-0.87, +0.41]
  pattern           29.60  +0.25 [-0.41, +0.87]              (ceiling)
  corr              29.44  +0.09 [-0.65, +0.81]   -0.16 [-0.79, +0.48]
  lr-pattern        29.23  -0.12 [-0.86, +0.60]   -0.37 [-1.03, +0.29]
  lr+qtype          29.25  -0.10 [-0.82, +0.61]   -0.35 [-0.97, +0.27]
  lr+qstat          29.25  -0.10 [-1.02, +0.80]   -0.35 [-1.21, +0.53]
  lr+verbosity      29.74  +0.39 [-0.49, +1.23]   +0.14 [-0.65, +0.95]
  lr+rank           30.52  +1.16 [+0.34, +1.96]*  +0.92 [+0.23, +1.63]*
  lr-full           30.20  +0.85 [-0.02, +1.70]   +0.60 [-0.16, +1.38]
  single-trunc      28.89  -0.46 [-1.49, +0.55]   -0.71 [-1.66, +0.26]   [control]
  count x rank      29.98  +0.63 [+0.27, +0.99]*  +0.38 [-0.28, +1.08]   [simple]
```

`count` reproduces 29.35 and `pattern` reproduces 29.60 from
`analysis/weighting_schemes.py` exactly, so the new harness is scoring on the
same terms as the old one.

### 1.1 Why this is not just another weighting scheme

`pattern` upper-bounds **every rule that reads only who asserted a claim** —
including correlation-aware and omission-aware ones, because the support pattern
already encodes who agreed and who stayed silent. At n=8 that ceiling is +0.25
and not significant. So the 18 Aug conclusion was right as far as it went: no
re-weighting of the support pattern can rescue the method at full pool size.

`lr+rank` clears the ceiling by +0.92 (significant) because rank is not a
function of the support pattern. The signal it uses:

```
  QAMPARI precision by position in the agent's list
    rank  1    2    3    5    9   11   16   21   26
    prec 29.2 31.4 30.4 26.6 16.7 15.8 11.8  8.9  6.3   %
```

and by how much the agent said on that question:

```
  items the agent listed    0-4   5-9  10-14  20-24  30-34  50+
  precision of those items 22.5  34.2   26.3   16.6   13.3   1.9  %
```

Kimi's median list is 13 items and its longest is 2431. One global weight
reports a single number for both.

### 1.2 The controls, which are what make it believable

- **`single-trunc`** — the best single agent's list, cut at a cross-fitted k.
  **28.89, below counting.** If truncation alone got to 30.5 the finding would
  be "short lists score better under F1" and the ensemble would be doing no
  work. It doesn't. Run this control before believing any rank result.
- **`count x rank`** — keep if (≥ θ agents assert) AND (min rank < R). Two
  integers, no per-model weights. **+0.63 over counting, significant.** So about
  half the gain is available from a rule you can state in one line; the per-agent
  rank coefficients carry the rest.

### 1.3 What this answers from the supervisor's ranked list

| # | idea | status |
|---|---|---|
| 1 | support-pattern reliability `P(T \| who supports)` | done — it IS the ceiling, +0.25 ns at n=8 |
| 2 | question-dependent weights `w_i(q)` | tested via QAMPARI's 5 question sources: **+0.00** |
| 3 | assertion + omission modelling | done 18 Aug (`nb-full`), +0.10 ns |
| 4 | error-correlation / diversity | **new, and null** — see below |
| 5 | semantic canonicalisation | negative result, 18 Aug (LLM clustering −6 F1) |
| 6 | `P(T \| q, c, support pattern)` | **this is the one that works** |

On (4): the arm is `score = Σ w_m z_m − λ Σ_{m<m'} ρ_mm' z_m z_m'`, with ρ the
error correlation estimated from co-assertion on WRONG claims only. **λ = 0 was
selected in all five folds.** Two weak agents hallucinating together is a real
phenomenon, but it is already priced into the support pattern, and the pattern
ceiling says there is nothing left there to collect.

On (6): the useful content feature turned out to be *rank and verbosity*, not
question domain. Worth saying in the paper — the obvious reading of "condition on
the question" is topic/domain, and on QAMPARI that is worth nothing.

### 1.4 It does NOT generalise to ASQA — and that constrains the claim

`analysis/asqa_rank.py`, same arms, same cross-fitting, ASQA under DR*. The
analogues are sentence index inside the author's response, and how many
sentences that author wrote.

```
  arm              DR*   STR-EM  ROUGE-L         vs count      vs pattern ceiling
  count          24.77    37.38    24.51       (reference)   -2.44 [-3.59,-1.37]*
  weighted       27.45    46.01    22.04  +2.69 [+1.64,+3.84]* +0.25 [+0.02,+0.54]*
  pattern        27.20    45.36    22.05  +2.44 [+1.37,+3.60]*            (ceiling)
  lr+rank        26.30    47.76    19.99  +1.53 [+0.40,+2.76]* -0.90 [-1.65,-0.16]*
```

`lr+rank` beats counting but sits **0.90 BELOW the pattern ceiling**,
significantly. On ASQA, position carries nothing the support pattern does not
already have.

Two readings, and they are not mutually exclusive:

- **Substantive.** A numbered list is an agent ranking its own candidates by
  confidence. Sentence order in prose is rhetorical structure, and carries no
  such ordering. If so, the mechanism applies to enumerative tasks only, and the
  paper should say so.
- **Methodological, and fixable.** Look at the columns: `lr+rank` has the
  *highest* STR-EM (47.76) and the *lowest* ROUGE-L (19.99). It is keeping more
  content. That is because the logistic is fitted to the proxy label "does this
  cluster cover an interpretation?", which is recall-flavoured, while DR
  penalises length. The scorer and the fitting objective are misaligned on ASQA
  in a way they are not on QAMPARI, where set-F1 and the per-claim correctness
  label agree. **Refitting against a length-aware label is the obvious next
  experiment and it is free.**

Until that is run, state the QAMPARI result as holding for enumerative answer
formats, not for long-form generally.

## 2. The crossover does not replicate on ASQA. It reverses.

`analysis/asqa_ensembles.py` — all 42 ensembles of size 3–6 from the 6 ASQA
agents, scored under DR*, 2-fold cross-fitted, same protocol as
`analysis/ensemble_sizes.py`. Clustering is **redone per ensemble** (clustering
once on all six and intersecting would let an excluded agent's sentence bridge
two clusters, and could hand the ensemble a representative no member wrote).

```
          QAMPARI  (8 agents, set F1)          ASQA  (6 agents, DR*)
  size   count  weighted  wgt-cnt        count  weighted  wgt-cnt
    3    22.15    24.40    +2.25         25.88    26.71    +0.83
    4    23.69    25.59    +1.90         25.30    26.74    +1.44
    5    26.17    26.56    +0.40         24.70    26.90    +2.19
    6    27.74    27.38    -0.36         24.27    27.01    +2.74

  weighted > count, significantly
    3      39/56  (70%)                    12/20  (60%)
    4      39/70  (56%)                    12/15  (80%)
    5      20/56  (36%)                     6/6  (100%)
    6       7/28  (25%)                     1/1  (100%)
```

Two clean monotone trends running in **opposite directions**. The 18 Aug claim —
"weighting works at small ensembles and stops working at large ones, because the
support count becomes a sufficient statistic" — is true on QAMPARI and false on
ASQA.

A second thing to carry into the paper: **on ASQA, counting never beats the best
single agent, in any of the 42 ensembles**, and falls further behind as the pool
grows (−0.70 at n=3 to −2.26 at n=6). On QAMPARI counting overtakes best-single
at n=6. MA-count is the arm we are proposing as the contribution, so this needs
to be stated rather than discovered by a reviewer.

### 2.1 The crossover is a property of PATTERN rules. Rank does not cross over.

`analysis/rank_crossover.py` — all 210 QAMPARI ensembles, 2-fold cross-fitted,
same folds and same questions as `ensemble_sizes.py`.

```
                          GAIN OVER COUNTING
  size    n   best single   count   weighted   pattern     rank
    3    56      24.72      22.15     +2.25     +2.73     +4.12
    4    70      26.00      23.69     +1.90     +2.57     +4.16
    5    56      26.77      26.17     +0.40     +1.13     +2.74
    6    28      27.18      27.74     -0.36     +0.36     +1.86
   (8)    1      27.99      29.35     -1.25     +0.25     +1.16   [beyond_pattern.py]

  ensembles where the arm SIGNIFICANTLY beats counting
    3            39/56     45/56     56/56
    4            39/70     44/70     70/70
    5            20/56     23/56     50/56
    6             7/28      7/28     21/28
```

**Validation:** the `count`, `best single`, `weighted` and `pattern` columns and
all of the weighted/pattern significance counts reproduce `ensemble_sizes.py` and
`crossover_controls.py` exactly. Two independent harnesses, same numbers.

The reading:

- All arms decay with ensemble size. The 18 Aug mechanism survives — the
  information available to a who-said-what rule genuinely does shrink.
- But **rank keeps a significant margin at every size**, including n=6 (+1.86,
  21/28) and n=8 (+1.16), where `weighted` has gone negative and the pattern
  ceiling is null. Within the range we can measure, pattern-based weighting
  crosses over at n≈5–6 and rank-based weighting never does.
- Rank's margin is roughly **1.5–5× the pattern ceiling's** at every size, which
  is the same statement as §1 made at n=8, now shown to hold across the whole
  curve rather than at one pool size.

So the crossover is real but it is a fact about *support-pattern* rules
specifically, not about aggregation. That is a sharper and more defensible claim
than the one it replaces.

## 3. What predicts the direction: how much a solo assertion tells you

Not ensemble size, and not pool heterogeneity.

```
                       P(correct | k=1)   P(correct | k>=2)   ratio   solo share
  QAMPARI (entities)         1.2%              19.9%          0.06      87.1%
  ASQA (sentence clusters)  22.5%              47.5%          0.47      86.9%
```

Both benchmarks are ~87% solo candidates. The difference is what a solo
assertion *means*. On QAMPARI a solo claim is 16× less likely to be right than a
supported one, so thresholding on count is a near-perfect filter — and it gets
sharper as the pool grows, because the top of the ladder rises (`P(correct | k)`
runs 1.2 → 11.1 → 17.4 → 27.2 → 36.5 → 46.3 → 51.9 → 56.5%). Weighting has less
and less left to add.

On ASQA a solo cluster is only 2× worse than a supported one, so a count
threshold discards most of the content for very little precision. The only thing
left to discriminate on is *who* said it — and that gets **more** valuable as the
pool grows, because more agents means more solo clusters to sort through.

**Proposed diagnostic, and it is cheap:**

> **solo ratio** = `P(correct | k=1) / P(correct | k>=2)`
>
> Low (≲0.15) → counting is close to optimal, weighting is redundant.
> High (≳0.4) → counting cannot filter, weighting is necessary.

It is computable on any new dataset from cached generations alone, before any
method is implemented. **This is the screen to run on candidate third datasets**
— it says in advance whether the dataset can adjudicate our question at all,
which is exactly the trap QUEST and STR-EM-scored ASQA both fell into.

### 3.1 Pool heterogeneity is NOT the explanation — worth knowing, we predicted otherwise

```
  ASQA pool           DR*   words      QAMPARI pool          F1   items
    gpt-5.4          29.01    78         grok-4.3         27.99    10.5
    MAI-Thinking-1   27.34    80         Kimi-K2.5        27.99    71.0
    DeepSeek-V4      26.92    78         MAI-Thinking-1   23.90    15.3
    gpt-5.4-mini     26.15    68         gpt-5.4          18.50    19.0
    grok-4.3         24.53    80         DeepSeek-V4      17.02    29.1
    gpt-5.4-nano     19.82    70         gpt-5.4-mini     16.24     5.0
                                         gpt-5.4-nano      9.61    25.3
                                         Cohere-cmd-a      5.82     6.7
  best/mean(rest)     1.16                                  1.65
  coeff of variation  0.125                                 0.439
```

The prediction was: heterogeneous pool → weighting matters; homogeneous strong
pool → counting is already fine. **The observed pattern is the reverse across
benchmarks.** ASQA's pool is much more homogeneous and is where weighting wins
biggest.

The prediction does hold *within* a benchmark — `corr(dominance, weighted −
count)` is +0.488 across QAMPARI's 210 ensembles. But on ASQA the same
correlation is only **+0.107**. So dominance is a within-benchmark modifier, not
the thing that separates the two benchmarks. The separator is the solo ratio.

## 6. What I would do next, in order

1. **Refit `lr+rank` on ASQA against a length-aware label** (§1.4). The current
   proxy label is recall-flavoured and DR is not; that misalignment is the most
   likely reason the arm keeps too much content. Free, cached, and it decides
   whether the rank claim is enumerative-only or general — which is the single
   biggest open question in the paper right now.
2. **Run the solo-ratio screen on every candidate third dataset** before
   implementing anything for it. This is the cheapest way to avoid a third QUEST.
3. **TriviaQA canonicalisation** — free, cached, and it is the control where
   published OW actually applies. Note its solo ratio will be near 1.0 (a single
   model's short answer is usually right), which by §3 predicts weighting should
   dominate counting there.
4. Deploy the OW pool once someone has run `az login`.

**The claim to defend, revised:**

> Multi-model atomic self-consistency is a strong naive baseline *when a solo
> assertion is strong evidence of being wrong*. Where that holds (QAMPARI) the
> support count is nearly a sufficient statistic and reliability weighting adds
> little at pool sizes ≥5; where it does not (ASQA) counting cannot filter at all
> and weighting is necessary, increasingly so as the pool grows. The solo ratio
> says in advance which regime a dataset is in.
>
> And the crossover that closes the first regime is a property of
> **support-pattern rules**, not of aggregation: conditioning on *where in its
> own output* an agent placed a claim beats the best possible support-pattern
> rule at every ensemble size from 3 to 8, including the sizes where every
> pattern rule is dead. Shown for enumerative answer formats; open on prose.
