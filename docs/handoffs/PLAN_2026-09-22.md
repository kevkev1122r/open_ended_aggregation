## 0. What we want

**Claim.** How an agent produced its answer carries evidence about each claim's
reliability, and that evidence does not depend on which agents are in the pool.
A synthesizer built on it can **swap the agents with no relabelling**.

**System (v1).** The full diagram is in `PIPELINE_2026-09-22.tex`, and is also
Figure 1 of `PLAN_2026-09-22.tex`.

```
responses → 1 LLM claim extraction → 2 exact match on → claim table
            (each response alone,     canonical form     (supporters · silent ·
             canonical form)                              contradicting)
          → 3 features → 4 scorer p(c) → 5 per-question budget → keep | band | drop
          → 6 LLM composer (reads band + contradictions + q + responses) → answer
```

**What "zero-label" should mean.** This is a decision for you. The data forces
it.

- **Zero-label on a new pool.** The scorer is trained once on a task and
  deployed with different agents, and no target labels are ever used.
  **Supported, strongly** (§1). This is the realistic multi-agent case: models
  change every month, the task does not.
- **Zero-label on a new task.** **Not supported on list-F1 benchmarks, and it
  cannot be.** The scorer's value is mostly deciding how many answers to keep per
  question, and on these benchmarks that is fixed by how each dataset built its
  gold. WebQSP's Freebase gold averages 76 answers; QAMPARI's is incomplete.
  - Test this only with a metric that doesn't depend on how the gold was built:
    judged claim precision plus recall against gold.
  - Otherwise report it as a boundary, not a headline.

**Decided 22 Sept: zero-label on a new pool.** Labelled data from the same task
with other agents may train the scorer; no labels from the new agents are used.
Cross-task is a stress test with a stated boundary.

**Where the LLM must earn its place.** Long-form composition, and judging the
uncertain claims. On lists the scorer alone may already be the best system. The
pilot decides (§3).

## 1. Findings

`analysis/pool_transfer.py`, `analysis/cut_rules.py`; results in
`results/pool_transfer*.json`, `results/cut_rules.json`, and the `*.log` files.

**Pool transfer works, and the identity gap is closed without labels.**
- Features: ~12 pool-invariant ones plus "self" normalisation, which measures
  rank and verbosity against each agent's *own* median list length. Label-free.

| QAMPARI, disjoint pools, question-disjoint | F1 | vs zero-label count |
|---|---|---|
| 4 → other 4 (70 transfers) | **27.63** | **+4.91, significant 70/70** |
| 3 → other 5 (56) | 28.14 | +4.57, 46/56 (1 loss) |
| 5 → other 3 (56) | 26.29 | +6.46, 56/56 |
| paper scorer, identity features, **target gold**, 4-agent pools | 28.25 | — |

- The transferred scorer beats counting even when counting's threshold is tuned
  on target gold (23.94, 4-agent pools).
- It gets within 0.4–1.2 of the fully supervised paper scorer.
- **Runway:** the gain does not shrink as the pool's best agent gets stronger
  (correlation +0.02 across 70 pools). This is unlike MAS-Orchestra, though our
  best-single range is narrow (24–28).

**Dead ends, measured:**
- Reliability features (agreement, Dawid–Skene, supervised) break transfer.
- Prior-shift recalibration: the estimated base rate collapses.
- Multi-source training does not help cross-task.
- "Size from counting, content from scorer" loses to counting at matched size.

**The scorer's value is per-question sizing, not reordering.** At the same output
size as counting, it is no better than counting (−0.2 to −0.6). Its gain comes
from choosing *how many* to keep per question, from verbosity and omission
signals.
- That is why it transfers across pools, which share a gold convention, but
  across tasks only where conventions match:
  - CWQ: +0.9 to +1.8 from every source.
  - WebQSP: −0.6 to −3.4.
  - QAMPARI from the KG datasets: −0.4 to −3.6.
- This corrects the earlier "ranking transfers, cutoff doesn't" framing.

**Position is real but modest, and the method leans on it far less than we
said.** `analysis/position_signal.py`, `position_signal.log`.

- **Real.** With support and list length controlled, per (claim, agent), later
  items are less often correct on all three datasets.

  | Solo claims, 6–100 item lists, top vs bottom depth quintile | Precision |
  |---|---|
  | QAMPARI | 5.6% → 1.8% |
  | CWQ | 7.2% → 4.2% |
  | WebQSP | 11.8% → 7.4% |

  The same holds for shared claims (QAMPARI 36% → 20%, WebQSP 61% → 39%).

  It survives on WebQSP's near-exhaustive gold, so it is not only a "famous
  entities are in the gold list" artefact. QAMPARI's steeper gradient may partly
  be one. It reverses on 1–5 item lists (`rank_effect.py`).
- **The gain over counting, decomposed.** Zero-label 4|4 transfer, +4.91 over
  counting in total:

  | Component | F1 over counting |
  |---|---|
  | per-question budget on support alone | +2.67 |
  | question context (#candidates, mean support) | +0.78 |
  | rank + verbosity + omission together | +1.46 |

  - Dropped one at a time: rank −0.51, verbosity −0.42, omission −0.01.
  - Pooled, pool-invariant omission adds nothing. The sweep's +1.65 for omission
    came from knowing *which* agent was silent, which is identity.
- **Decided 22 Sept: position stays in the scorer.** Removing it is significantly
  worse in 40/70 splits, it needs no labels, and its direction is the same on
  all three datasets. What changes is the framing, not the features.
- **So the headline mechanism is sizing each answer from the crowd's agreement
  structure.** Per-claim behavioural signals are a real but secondary +1.5.
  Framing and novelty should follow that. Rank was already downgraded in
  `NOVELTY_CHECK.md`: generated-position confidence has prior art.
- For long-form, keep sentence position as a feature, but run the with/without
  ablation before trusting it: first sentences are often hedges, and the effect
  reverses on 1–5 item lists. The contradiction signal (slot→value) is the
  stronger bet there.

**Long-form: sentence clustering merges contradictions.**
- Hand-check marked 22 Sept (`docs/ASQA_MATCHING_HANDCHECK.md`, rule and
  per-item reasons in the file):
  - Only 12/20 groups state one fact. 5/20 merge **contradicting values** (A17
    91.5 vs 47.5 sacks, A19 41 vs 43 parks, A4 2019 vs 2020, A13, A3), and 3
    bundle different facts.
  - Of 20 near-miss pairs below the threshold, 7 are missed matches and 3–4 are
    same-slot contradictions (B7, B9, B16).
- 87% of clusters are single-agent.
- Sentence similarity cannot tell agreement from contradiction, so
  contradicting agents are counted as support.

**CWQ scoring is broken by surface-form mismatch (found 22 Sept, before any
spend).** The agents write "Arabic"; gold stores "Arabic Language". The agents
write "1960"; gold stores "1960 NBA Finals". Exact matching scores these correct
answers as wrong.

| | Zero-scoring questions, exact match | With suffix fix | Union F1, exact → fixed |
|---|---|---|---|
| CWQ | 45% | 27% | 21.3 → 27.4 |
| WebQSP | 19% | 13% | 28.8 → 33.9 |
| QAMPARI | 21% | 20% | 23.4 → 24.5 |

- A pilot on CWQ would mostly measure which arm writes "X Language". **The pilot
  is on hold** until its benchmark is decided.
- Every existing CWQ number, including the paper's and the cross-task transfer
  above, carries this distortion. Audit CWQ/WebQSP gold matching before ACL.

**Gold is very incomplete.** Union precision is 4–11% on all three list sets.
Any arm that adds correct but unlisted items, such as the LLM or `solo` arms, is
penalised.

## 2. Design decisions this implies

1. **Scorer:** pool-invariant + self-normalised, with position and verbosity
   features kept, and no reliability block. The paper scorer becomes an in-pool
   supervised reference.
2. **One claim splitter for every format: LLM canonical extraction.** An LLM
   reads each response *separately* and rewrites every claim in canonical form:
   full official entity names ("MGM" → "Metro-Goldwyn-Mayer"), numbers as plain
   values, and for prose a slot → value pair with consistently phrased slots.
   Matching across agents is then exact string comparison, so the LLM never
   judges whether two different claims are the same. This replaces both the
   regex list parser and the sentence-embedding clustering.
   - *Why not LLM clustering:* the 18 August attempt merged across agents and
     made false merges ("Yale Law School" with "University of Michigan Law
     School"). It kept one representative per cluster, so a false merge deleted
     a correct answer. Per-response canonicalisation has no merge step.
   - *Its failure mode is inconsistency:* two calls may canonicalise one entity
     differently. That is a missed match, which lowers a support count; it does
     not delete an answer.
   - *Contradiction:* values in the same slot compete, so a **contradicting agent
     ≠ a silent agent**. Lists never had this signal. All scorer features port.
3. **Long-form metric:** judged fact precision × STR-EM recall over ASQA's
   interpretations. DR is length-dominated, which makes length a gold-convention
   choice again.
4. **Composer = band:** confident claims decided by the scorer; the LLM rules on
   the uncertain band and writes. Answer-count estimation by an LLM is capped at
   about 1–2 F1 (true-count oracle), so it is not the LLM's job.
5. **Every LLM result is reported with its output size** (now logged), and
   against the no-LLM `scorer` reference.

## 3b. Pilot RESULT (QAMPARI, 80 questions, run 23 Sept)

Zero-label on a new pool: the scorer was fitted on the gpt-5.4 agents'
train-half answers and applied to the 5 Azure agents on test-half questions.
Synthesizer gpt-5.4, low reasoning effort. Billed $5.09, plus $0.64 for the
smoke test; ~$7.27 of the $13 remains. Files: `results/synth_rungs_qampari_n80.json`,
`synth_prompts_qampari_n80.jsonl`, `synth_cache_qampari.jsonl` (paid cache, never
delete), `synth_pilot_analysis.log`.

| Arm | F1 | Precision | Recall | Items |
|---|---|---|---|---|
| text (plain LLM synthesis) | 31.12 | 32.68 | 40.19 | 24.1 |
| scorer alone, no LLM | 31.03 | — | — | 10.8 |
| pscramble | 30.37 | 32.03 | 37.09 | 18.5 |
| p (the system) | 29.30 | 33.37 | 34.41 | 15.8 |
| solo (synthesizer alone) | 28.90 | 36.66 | 27.42 | 6.8 |

- **No difference is significant.** 95% CIs are about ±3 F1 at n=80:
  p − pscramble −1.07 [−4.20, +1.67]; p − text −1.81; text − scorer +0.09.
- **The LLM does read the numbers.** It outputs 24.6% of candidates shown with a
  high p and 0% of those shown with a low p. But correct p helps its selection no
  more than scrambled p does: the correlation of its output with correctness is
  0.33 vs 0.34. The table mostly makes it cut harder, which lowers recall.
- At the LLM's own output size, its picks beat the scorer's top-k by +1.3 (ns).
  A post-hoc hybrid (the scorer sets the size, the LLM picks) gives +0.36 (ns):
  no gain.
- The LLM adds almost no items of its own (0–0.8% of outputs; 1 correct).
- **Pre-registered reading:** row 3 applies. The scorer ties the best LLM arm, so
  **lists do not need an LLM**. The no-LLM scorer matches gpt-5.4 synthesis at
  zero inference cost. The synthesizer contribution has to come from long-form
  answers (writing, resolving contradictions), as planned.

Reading:
- **The claim table, p and the band do not help the composer on ASQA; the band
  hurts.** The loss is recall: STR-EM drops 1.3–3.6 points and answers get

**What this changes.** v1 as built (a filter-style table in front of the
composer) is not the method for long-form. If the table is to help on ASQA it
has to push *recall*: e.g. list every slot and ask the composer to cover each,
with p used only to choose *between values within a slot*, never to drop a slot.
That is a new arm and needs new money (~$0.035 per question for all arms;
~$0.57 left).

**QAMPARI** still needs judged recall (pool judged-correct items across arms as
an extended gold) before any list claim is written up; free with the cached
judge labels plus one judge pass per arm's new items.

## 3a. v2: internal model signals (after v1's baseline comparisons)

Added 22 Sept. Only if the scorer has room to improve. Each step is measured
the same way as position: F1 with and without, in the zero-label pool transfer.

| Step | Signal | Access | Zero-label? | Decision |
|---|---|---|---|---|
| 1 | **Per-claim token log-probabilities**: the model's confidence while writing each claim | Many APIs return them (OpenAI, some Azure deployments) | Yes, if normalised against each agent's own typical values, as done for verbosity | **Do after v1** |
| 2 | Hidden-state probes | Open-weight models only | Only with unsupervised probes; a trained probe per new model needs that model's labels | Maybe, as an "open-model setting" extension |
| 3 | KV-cache or hidden-state sharing between agents | Open weights, usually one model family | — | **Skip**: agents reasoning together, not merging finished answers |

- **Why step 1:** UAF uses perplexity-style signals but one number per
  response. Per-claim log-probabilities say *which item* in a list the model was
  unsure about. It is a direct head-to-head with UAF, and it keeps the
  closed-model setting.
- **How it enters:** new scorer features, such as the supporters' mean
  self-normalised log-probability. Nothing else in the pipeline changes.
- **Cost:** re-query a sample with log-probabilities on. Check first which pool
  models expose them.
