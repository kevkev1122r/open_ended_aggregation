## 2. What changed in the paper this session

### 2.1 Reframed, at the mentor's request

The note was *"simplify the framing"* and *"present it as more general than a
set-level task."* The reframe came from a ChatGPT analysis the mentor pointed at;
its spine is **votes versus observations**.

For a claim $c$, $S(c)$ is the set of asserting agents and $B(c)$ is what their
generations reveal about it. Majority voting reads $|S(c)|$, reliability
weighting reads $S(c)$, we read both. The generality argument is structural: an
agent that generates does not cast a vote, it produces a structured artifact, and
reducing that to an assertion indicator discards the rest.

| location | change |
|---|---|
| title | `Beyond Votes: Generation Behaviour as Evidence in Multi-Agent Aggregation` |
| abstract, §1.1, §1.3 | rebuilt on the hierarchy |
| §1.5 | contributions cut 6 → 4 |
| §2 | `B(c)` defined next to `S(c)` |
| §4.1 | new "Why these benchmarks": set-valued data is a *measurement constraint*, since a filter needs a metric scoring precision and recall |
| §6.1, §7 | aligned |

"Set-valued" is out of the title and abstract; it survives twice in the body,
both describing someone else's work.

### 2.2 New theory section, §3.2

Three propositions. Full statements in `iteration2.md` §2.

- **P1, information dominance.** $R^*(S,B) \le R^*(S)$. Elementary, and the
  section says so. Paired with the finite-sample caveat, which the ASQA result
  instantiates.
- **P2, behaviour as likelihood evidence.** Collapsing $X_{ic}$ to an assertion
  indicator recovers reliability weighting, and with symmetric errors recovers
  BMV's $\log(x/(1-x))$. **Reliability weighting is now nested inside the
  framework rather than opposed to it.** This is the most useful thing the
  section does.
- **P3, the decision rule.** Produced a closed form the paper did not have:
  keep candidates while $p_{(k+1)} > \tfrac12 \widehat{F_1}(k)$. Verified against
  both panels of Figure 3.

`amsmath` was added to the preamble. Note six pre-existing `\text{}` uses were
relying on the NeurIPS style pulling it in.

### 2.3 One overclaim removed

§3.1 said the pattern lookup bounds every weighting rule *by construction*. It
does not: the lookup is a finite-sample shrunk estimator, and set F1 is not
decomposable, so a rule making joint decisions across a question's candidates
could in principle beat any per-candidate threshold rule. Narrowed to *the
strongest claim-local, identity-only rule we can estimate*, with a paragraph
naming both limits. Related Work and Conclusion updated to match.

### 2.4 ASQA story rewritten, §5.5

The old section compared us to reliability weighting. **The right yardstick is
the best single agent**, and against it counting falls below in 39 of 42
ensembles and never significantly beats it, with the deficit widening from −0.70
at n=3 to −2.26 at n=6. So on ASQA the whole claim-level family is competing to
match one agent. Our loss reads very differently in that light.

The mechanism chain, each link measured: solo ratio 0.47 vs QAMPARI's 0.06 →
counting deletes good content → weighting recovers because per-agent weights cut
selectively → our confidence slot is empty because sentence position is flat at
ASQA lengths (ρ = −0.029, n = 4,064) → so the scorer adds variance, and sits
below the ceiling it stacks on.

### 2.5 New result: the identity null is a bound, not underpowered

New module `analysis/power_check.py`, output `results/power_check.json`. This is
sensitivity at the achieved n, **not observed power**, which the
`statistical-power` skill is explicit should never be reported.

| comparison | observed | 95% CI | MDE @80% | TOST margin |
|---|---|---|---|---|
| pattern vs count | +0.30 | [−0.35, +0.92] | **0.92** | **±0.83** |
| scorer + budget vs count | +2.50 | [+1.69, +3.28] | 1.13 | ±3.14 |

The design detects 0.92 F1 at 80% power and establishes equivalence to zero
within ±0.83. The same design resolves +2.50 comfortably. **A small effect
measured precisely, not a large one measured badly.** Added to §5.1 as claim
C051 against E127.

This required patching `weighting_v5.py` to dump per-question scores, which it
computes and previously discarded. That patch is **kept**; it writes
`results/weighting_v5_perq_seed0.json`. The rerun reproduced the headline
exactly, which is an independent reproducibility check.

## 5. Do NOT redo this

**The ASQA pattern-stack feature was implemented, run, and reverted.**

The QAMPARI scorer takes the pattern lookup's own prediction as an input feature
(`weighting_v3.py:115`, filled `weighting_v5.py:123`). The ASQA scorer did not,
so it saw the support pattern only through additive per-agent indicators. This
looked like it might explain why the ASQA arm sits below the pattern ceiling, and
it was listed as the top open item.

It was added and swept over all 42 ensembles. **It is worth +0.01 DR\* on
average**, helps significantly in 5 ensembles and hurts in 1, and is −0.18 at
size 6. With it in place the scorer still sits 0.29 below the ceiling on average,
widening with pool size.

Consequences, all already applied:

- code reverted (`asqa_ours_ensembles.py` restored from backup, 0 stack references);
- the §5.5 sentence claiming the omission "plausibly costs the ASQA arm" was
  **false** once measured, and is replaced with the measured result (C050 now
  cites E128, `asqa_stack.log`);
- `iteration2.md` item 1 marked closed.

The upside: the mechanism story in §5.5 is now *better* supported, because the
pattern information has been controlled for and the gap survives.

`asqa_stack.log` is retained as the evidence. Do not re-run this.
