# Kernel-Weighted Aggregation for open-ended answers — pilot findings

**Status.** Sections 1–8 are a synthetic pilot. **Section 0 is a real-data test** run afterwards
on real text with real embeddings, and it is now the most important part of this document — it
validates the central assumption and simultaneously shows the synthetic pilot was too easy.

---

## 0. THE MAKE-OR-BREAK TEST, on real data

The whole method rests on one assumption:

```
  log P(agent produces answer a | truth is s)  =  α + β · sim(a, s)
```

Two things must hold. **(G)** errors must land near the truth in embedding space, or similarity
carries no signal. **(L)** log-odds must fall *linearly* in similarity, or the aggregator is
misspecified.

Data — both real, nothing simulated:
- **TruthfulQA** (817 questions): per question a best answer, human-written correct paraphrases,
  and human-written *plausible misconceptions*.
- **HaluEval QA** (10,000 questions): per question a right answer and a hallucinated answer that
  was **generated by a real model** (ChatGPT).

Embeddings: `all-MiniLM-L6-v2`, cosine similarity.

### (G) Do real model errors land near the truth? — YES, strongly

```
  similarity to the right answer            mean     sd
    the model's OWN wrong answer            0.302   0.192
    another question's wrong answer         0.079   0.088

    Cohen's d = 1.49
    the model's own error is nearer the truth in 86.7% of questions
```

A model's mistakes are not scattered. They cluster around the truth. **There is signal to exploit.**

### (L) Is the log-linear law real? — YES, R² = 0.99

Case-control over 4,000 real model outputs against 32,000 controls, binned by similarity:

```
  straight-line fit:  log-odds = 10.69 · sim − 1.86
    R² (linear)     0.990
    R² (quadratic)  0.991      ← curvature buys +0.001
```

Ten bins, dead straight, and the extra quadratic term buys essentially nothing. **The assumed
functional form is the right one**, and the fitted slope *is* β — measured at 10.69 for this model.

### But the geometry is much harder than I simulated

```
  similarity to the correct answer          measured        I had assumed
    correct paraphrase                        0.626             0.975
    plausible WRONG answer                    0.580             0.750
    unrelated answer                          0.058             0.300

    correct-vs-plausible-wrong gap            0.046             0.225   ← 5x too generous
```

Correct paraphrases and plausible wrong answers sit **almost on top of each other** (see
`results/figures/R1_real_data_test.png` — the green and orange histograms overlap nearly
completely). My synthetic pool made that discrimination five times easier than it really is.

### Re-running the pilot with the measured geometry

Fully deployable variant (no oracle anywhere), and with the **baseline tuned to its own best
threshold** so it isn't a strawman:

```
  MV-cluster, τ swept over [0.30 … 0.90], best τ = 0.60      88.27
  KWA-EM (deployable)                                        93.27
                                              advantage      +5.00
```

**The advantage got bigger, not smaller** (+1.6 synthetic → +5.0 realistic). The reason is the
overlap itself: when correct and plausible-wrong answers are 0.05 apart, *no* hard threshold can
separate them — cluster too loosely and you merge wrong answers in, too tightly and you split
nothing. A soft kernel never has to make that binary call. **Real geometry is precisely where
hard clustering breaks and soft weighting wins.**

## 0.5  STRESS-TESTING THAT RESULT — and it does not fully survive

Three tests designed to break the claim, not confirm it (`robustness_test.py`,
`control_gradient.py`).

### T1 — Encoder robustness: PASSES

Four unrelated encoders, HaluEval QA, random controls:

| encoder | dim | β | R² linear | R² quad |
|---|---|---|---|---|
| all-MiniLM-L6-v2 | 384 | 10.87 | 0.993 | 0.994 |
| all-mpnet-base-v2 | 768 | 11.61 | 0.990 | 0.995 |
| bge-small-en-v1.5 | 384 | 14.61 | 0.959 | 0.991 |
| all-distilroberta-v1 | 768 | 11.49 | 0.988 | 0.992 |

β moves — expected, each encoder has its own similarity scale. R² does not. Not a MiniLM artefact.

### T2 — Task family: PARTLY PASSES

| task | β | R² linear | R² quad | Cohen's d |
|---|---|---|---|---|
| qa | 10.88 | 0.991 | 0.991 | 1.50 |
| dialogue | 6.95 | **0.858** | 0.989 | 1.89 |
| summarization | — | no fit | — | 5.23 |

Dialogue is already visibly worse as a *straight line* (0.858) while remaining excellent with
curvature (0.989). Summarization couldn't be fit at all with random controls — positives sit at
0.73 and controls at 0.10, so the supports barely overlap.

### T3 — Control design: **THE HEADLINE CLAIM BREAKS**

The first pass drew controls from *random* other questions, so they were all off-topic. That
alone can manufacture a linear-looking trend. Redrawing controls from the **nearest** other
questions (topic-matched near-misses):

| task | controls | β | R² linear | verdict |
|---|---|---|---|---|
| qa | random | 10.96 | 0.991 | holds |
| qa | **hard (nearest)** | **2.60** | **0.685** | **breaks** |
| dialogue | random | 7.01 | 0.858 | weak |
| dialogue | **hard (nearest)** | **2.33** | **0.349** | **breaks** |
| summarization | hard (nearest) | 11.34 | 0.977 | holds |

**Placebo passes everywhere** — randomly relabelling which answers were "produced" collapses the
slope to |β| ≤ 0.088 with R² ≤ 0.062. So the pipeline is not inventing structure from nothing.
The machinery is sound; the functional form is what fails.

### The gradient — what is actually true

Sweeping control hardness continuously (`results/figures/R2_control_gradient.png`):

```
  controls =    r=1     r=2     r=5    r=10    r=50   r=200  r=1000  random
  β            2.60    2.84    3.32    3.81    5.36    7.45   10.57   10.87
  R² straight  0.685   0.717   0.757   0.790   0.853   0.928   0.975   0.993
  R² curved    0.987   0.979   0.982   0.982   0.985   0.972   0.983   0.994
```

Read the bottom row. **Allowing curvature, R² stays at 0.97–0.99 across the entire gradient,
including the hardest regime.** The relationship is real, smooth and highly predictable
throughout. What collapses is specifically the assumption that it is a *straight line*.

So the honest three-line verdict:

1. **Errors cluster near the truth — bulletproof.** Placebo passes, 4 encoders, 3 task families,
   Cohen's d 1.5–5.2.
2. **β is not a constant.** It runs from ~2.6 to ~11 depending on how topically spread the
   candidate pool is. Most of the original R²=0.99 was a topic-matching effect.
3. **`log P = α + β·sim` is misspecified in the regime that matters.** The aggregator chooses
   among answers to the *same* question — all topic-matched — which is exactly the r=1 end where
   the straight line fits worst (R² 0.35–0.69) and curvature fits nearly perfectly (0.96–0.99).

### One caveat that cuts the other way

In HaluEval QA, 30.2% of questions have a nearest neighbour whose *correct answer* is >0.8
similar, and 23.6% >0.9 — the dataset is built from HotpotQA and contains many near-duplicate
questions. So the "hard controls" are contaminated with answers that are effectively **correct**,
which flattens β. **β = 2.60 is a biased-low bound**; the true hard-regime value sits somewhere
between 2.6 and 11.

## 0.6  TRIPLE REPLICATION — three independent datasets, three encoders, bootstrap CIs

`triple_replication.py`. Same protocol on three corpora that share no construction pipeline,
chosen to differ in **where the wrong answers come from**:

| dataset | n | wrong answers are… |
|---|---|---|
| HaluEval-QA | 3000 | **generated by a model** (ChatGPT), HotpotQA questions |
| TruthfulQA | 817 | written by **experts** as adversarial human misconceptions |
| SciQ | 3000 | written by **crowdworkers** as school-science exam distractors |

### Result 1 — the effect is bulletproof: 9/9 cells

Cohen's d ranges **1.43 to 3.14** across all nine dataset × encoder cells. The placebo
(randomly relabelling which answers were produced) passes in all nine: max |β| = 0.277,
max R² = 0.153, against real β of 2.6–20.6. **Errors cluster near the truth. Not a corpus quirk,
not an encoder quirk, not an artefact of the pipeline.**

### Result 2 — β is not a constant: it spans 2.6 → 20.6

Across cells and control settings. Within a single cell it moves 4–7× as controls go from
topic-matched to random. β is a property of *(encoder, corpus, candidate-pool spread)*, not of a
model. Any method that treats it as a fixed number is wrong.

### Result 3 — whether a straight line works depends on where the errors came from

At the hardest (topic-matched) controls, R² for a straight line vs allowing curvature, with
bootstrap 95% CIs:

| dataset | encoder | straight | curved | CIs |
|---|---|---|---|---|
| HaluEval-QA | MiniLM-L6 | 0.685 [0.58,0.76] | 0.987 [0.93,0.99] | **disjoint** |
| HaluEval-QA | mpnet-base | 0.691 [0.60,0.76] | 0.970 [0.91,0.98] | **disjoint** |
| HaluEval-QA | bge-small | 0.824 [0.73,0.89] | 0.991 [0.94,0.99] | **disjoint** |
| TruthfulQA | MiniLM-L6 | 0.441 [0.35,0.52] | 0.959 [0.90,0.98] | **disjoint** |
| TruthfulQA | mpnet-base | 0.426 [0.34,0.50] | 0.956 [0.89,0.97] | **disjoint** |
| TruthfulQA | bge-small | 0.527 [0.42,0.63] | 0.941 [0.86,0.98] | **disjoint** |
| SciQ | MiniLM-L6 | 0.983 [0.93,0.99] | 0.983 [0.93,0.99] | overlap |
| SciQ | mpnet-base | 0.991 [0.95,0.99] | 0.994 [0.96,1.00] | overlap |
| SciQ | bge-small | 0.962 [0.89,0.98] | 0.988 [0.94,0.99] | overlap |

**Curvature is required in 6/9 cells, with non-overlapping bootstrap CIs — and the split is
perfectly clean by dataset, not by encoder.** All three encoders agree within each corpus.

The exception is the informative part. **SciQ is the one corpus whose wrong answers were written
independently of any model** — crowdworkers inventing plausible science terms. There, a straight
line fits fine (R² 0.96–0.99 even at the hardest controls). HaluEval's errors were *generated by
a model*, and TruthfulQA's were *engineered to fool models*; in both, errors pile up at the top
of the plausibility range, which saturates the response and bends the curve.

**That is the worst possible arrangement for the method's convenience: the two corpora that
actually represent model behaviour are the two where the linear form fails.**

### The verdict, with numbers behind every clause

1. **Errors cluster near the truth** — 9/9 cells, d = 1.43–3.14, placebo passes 9/9. Solid.
2. **β is not a constant** — 2.6 to 20.6. Must be estimated per deployment, never assumed.
3. **`log P = α + β·sim` is refuted for model-generated errors** — 6/9 cells, CIs disjoint,
   consistent across all three encoders.
4. **A curved kernel suffices everywhere** — R²_curved ≥ 0.94 in all 9 cells, including the
   three where linear already worked. Adopting curvature costs nothing and fixes the failures.

## 0.7  PROPER REGRESSION — which corrects two things above

`regression.py`. Everything in §0.5–0.6 binned similarity into 10 slices, fit a line to those 10
summary points, and compared R² by eye. That discards everything inside a bin and is not a
hypothesis test. The correct analysis is **logistic regression on the raw rows**:

```
  y = 1  answer a model really produced        x = similarity to the truth
  y = 0  a control answer                      logit P(y=1) = α + β·sim
```

which is *exactly* the assumed model, fit on all ~27,000 rows. Adding a `sim²` term and running a
likelihood-ratio test converts "the curve looks better" into a p-value. **Standard errors are
clustered by question** — each question contributes 1 positive and 8 controls, so naive SEs would
be far too small.

### Correction 1 — curvature is required in 9/9 cells, not 6/9

| dataset | encoder | β (95% CI) | z | bend coef | LR test p | AIC gain |
|---|---|---|---|---|---|---|
| HaluEval-QA | MiniLM-L6 | 3.96 [3.69, 4.24] | 28.5 | **+5.63** | <1e-16 | 109 |
| HaluEval-QA | mpnet-base | 3.74 [3.47, 4.01] | 27.2 | **+4.58** | <1e-16 | 74 |
| HaluEval-QA | bge-small | 7.07 [6.63, 7.51] | 31.4 | **+17.15** | <1e-16 | 133 |
| TruthfulQA | MiniLM-L6 | 8.23 | — | **+18.49** | <1e-16 | 384 |
| TruthfulQA | mpnet-base | 8.55 | — | **+18.95** | <1e-16 | 380 |
| TruthfulQA | bge-small | 14.20 [13.16, 15.24] | 26.7 | **+46.17** | <1e-16 | 319 |
| SciQ | MiniLM-L6 | 2.44 [2.25, 2.63] | 25.7 | **−3.87** | <1e-16 | 85 |
| SciQ | mpnet-base | 2.48 [2.29, 2.67] | 25.6 | **−3.93** | <1e-16 | 87 |
| SciQ | bge-small | 5.12 [4.71, 5.53] | 24.6 | **−9.40** | 8e-10 | 36 |

SciQ looked linear under binning only because 10 bins were too coarse to see its bend.
**§0.6's "6/9" was an artefact of my own crude method.**

### Correction 2 — the bend goes in OPPOSITE directions

This is new and the binned analysis could not have found it:

- **HaluEval and TruthfulQA (model-made / model-targeting errors): bend is POSITIVE.** The curve
  *accelerates* — as answers get very close to the truth, the odds of being a real error rise
  faster than linearly.
- **SciQ (hand-written exam distractors): bend is NEGATIVE.** The curve *saturates* — it flattens
  off at high similarity.

So "use a curve" is not enough guidance. The *shape* depends on where the errors come from, and
the two regimes bend opposite ways. A single fixed `g` will not serve both.

### Also: my binned β estimates were biased low

HaluEval/MiniLM, hard controls: binning gave **2.60**, the regression gives **3.96 [3.69, 4.24]**.
The regression estimate is the trustworthy one. Any β quoted in §0.5–0.6 should be read as
approximate.

### The sobering number: how much does similarity actually explain?

McFadden pseudo-R², linear → quadratic, hard controls:

| dataset | straight | curve | gain |
|---|---|---|---|
| HaluEval-QA | 0.053 | 0.059 | +0.006 |
| TruthfulQA | **0.379** | **0.454** | +0.075 |
| SciQ | 0.030 | 0.035 | +0.005 |

With 27,000 rows, p < 1e-16 is cheap — so read the effect size, not the p-value. **Similarity is a
strong discriminator on TruthfulQA and a weak one on HaluEval and SciQ.** (McFadden values are not
comparable to ordinary R²; 0.2–0.4 is considered a good fit, so 0.03–0.05 is modest but real.)

Practical reading: the kernel's discriminating power varies a lot by setting. It is a real signal
everywhere — the z-statistics are 25–62 with clustered SEs, the effect is not in doubt — but on
some corpora it provides a gentle tilt rather than a decisive separation. **Do not expect the
aggregator to work equally well everywhere.**

### What this changes about the method

The kernel should not be `β·sim`. It should be `β·g(sim)` for a monotone curved `g` — the data
says a quadratic already captures 98% of the variance. E7 in the synthetic pilot tested exactly
this misspecification and found KWA still led at every curvature from 0.5 to 2.0, so the method
tolerates it — but now the *direction* of the error is known and can be fixed rather than
tolerated. That is the top-priority change.

### What none of this establishes

- HaluEval hallucinations are one model's errors, deliberately elicited. Not a broad sample of
  behaviour across models.
- No end-to-end run on genuine multi-model free-form outputs — no local model or API key was
  available.
- Absolute similarity values are encoder-specific; only the ordering should be trusted.

## The synthetic pilot (sections 1–8)

Everything below this line is synthetic. Read it as "the machinery works and here is what broke",
not as evidence about real models — and discount the headline accuracy numbers by Section 0.

Answers the open question from Ai, Pan, Simchi-Levi, Tambe & Xu (ICML 2026),
*Beyond Majority Voting* (arXiv:2510.01499), §7: **"How to derive optimal weights for
open-ended questions?"**

---

## 1. The claim

Their OW derivation needs two facts, both manufactured by shuffling answer labels:

```
  (1)  P(agent j says s  | truth = s)  =  x_j
  (2)  P(agent j says s' | truth = s)  =  (1 - x_j)/(K - 1)    for EVERY s' != s
```

Fact (2) is what factors a constant out of the likelihood product and leaves
`weight × indicator` — a vote. Open-ended generation destroys it: there is no label set to
shuffle, and "Sydney" is a far likelier error than "photosynthesis" when the truth is
"Canberra".

**So the question is subtly mis-posed.** Working out the general posterior:

```
  score(s) = Σ_j log P(a_j | truth = s)
           = Σ_{j: a_j = s} log x_j  +  Σ_{j: a_j ≠ s} log e_j(a_j, s)
                                          ↑ depends on WHICH wrong answer — won't factor out
```

For open-ended you don't need a weight per agent. **You need a weight and a kernel.**

Proposed model — log-probability decays with semantic distance from the truth, at an
agent-specific rate:

```
  log P(a | truth = s)  =  α_j  +  β_j · sim(a, s)

  aggregator (KWA):   argmax_s  Σ_j  β_j · sim(a_j, s)
```

`β_j` is how sharply agent j concentrates near the truth. Strong agents have large β.

---

## 2. It is a strict generalisation, not a rival  (E1)

Set `sim(a,s) = 1{a=s}`. Then `P(correct) = e^β/(e^β + K − 1) = σ_K(β)` — **exactly the
paper's own σ_K parametrisation** (their §D.1) — and the rule collapses to OW.

| K | 2 | 3 | 4 | 6 | 10 |
|---|---|---|---|---|---|
| agreement with OW | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |

Multiple choice is the special case where similarity happens to be binary.

---

## 3. β is recoverable with zero labels  (E2)

EM with the truth as a latent variable. The M-step separates per agent, and each per-agent
objective (`linear − log-sum-exp`) is concave, so it's a reliable 1-D maximisation.

| unlabelled questions | 100 | 300 | 1000 | 3000 |
|---|---|---|---|---|
| corr(β̂, β) | 0.944 | 0.974 | 0.979 | 0.981 |
| RMSE | 1.00 | 0.99 | 0.83 | 0.78 |

```
  true β    8.00   6.00   4.00   2.50   1.50
  β̂ (M=3000) 6.30  5.65   4.04   2.48   1.49
```

**The error is almost entirely in the strongest agent, and it does not shrink with more
data.** Weak agents are pinned down to two decimals; the top agent is underestimated by 20%.
This is an identifiability limit, not sampling noise — at high β the agent nearly always
lands on the truth or a paraphrase, so β = 6 and β = 8 are behaviourally near-identical.
It is the same pathology as OW's weight error-bars blowing up as accuracy → 1.

## 4. Main comparison  (E4)

5 agents, 1500 questions, 5 seeds. Answer pool: truth + 2 paraphrases (count as correct)
+ 3 near distractors + 4 far distractors.

| method | accuracy % | ±sd | vs MV-exact |
|---|---|---|---|
| MV-exact | 79.84 | 0.86 | — |
| OW-L *(paper's method, exact match)* | 84.80 | 1.12 | +4.96 |
| OW-oracle *(paper's method, true accuracies)* | 85.64 | 0.92 | +5.80 |
| Best single agent *(clairvoyant)* | 85.83 | 1.04 | +5.99 |
| MV-cluster *(Universal Self-Consistency)* | 91.96 | 0.47 | +12.12 |
| **KWA-EM** *(label-free)* | **96.09** | 0.57 | **+16.25** |
| KWA-oracle *(true β)* | 96.13 | 0.49 | +16.29 |

Two things worth noting:

- **Label-free costs essentially nothing**: KWA-EM 96.09 vs KWA-oracle 96.13. The β
  underestimate in §3 doesn't hurt, because the aggregator only needs relative weights.
- **The paper's methods transplanted directly onto open-ended answers barely beat the best
  single model** (84.8 / 85.6 vs 85.8). That's the gap this project exists to close.

### The honest deployable number  (E10)

E4 lets EM normalise over the true answer pool. A real system can't. With **no oracle
anywhere** — EM normalising only over answers the agents actually produced:

| | MV-cluster | KWA-EM (deployable) | KWA-EM (oracle support) |
|---|---|---|---|
| N=5 agents | 93.09 | **94.69** | 95.91 |
| N=8 agents | 97.04 | **97.78** | 99.16 |

**The real gain over the strong incumbent is ~+1.6pp at N=5 and ~+0.7pp at N=8, not +4pp.**
Lead with this number, not E4's.

## 5. The mechanism is not what I predicted  (E5, E9) ← most interesting result

I predicted KWA would win by pooling votes split across paraphrases. **Wrong.** Varying the
number of paraphrases in the pool:

| paraphrases | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| MV-exact | 64.3 | 74.6 | 80.0 | 82.0 | 83.2 |
| MV-cluster | 64.6 | 84.9 | 91.2 | 94.9 | 96.2 |
| KWA-EM | 83.5 | 92.9 | 96.2 | 97.1 | 98.2 |
| **KWA − MV-exact** | **+19.2** | +18.3 | +16.2 | +15.1 | +15.0 |

The gap is **largest at zero paraphrases**, where vote-splitting cannot possibly be the
mechanism, and where MV-cluster degenerates to MV-exact (64.6 vs 64.3) because there is
nothing to cluster.

**The actual mechanism is triangulation.** Every agent's answer is drawn from a distribution
centred on the truth, so even a set of entirely wrong answers points at the truth
collectively. KWA finds the point of maximum weighted similarity to all of them — closer to
a weighted geometric median than to a tally.

### This breaks a ceiling that binds every vote-based method  (E9)

Any method that outputs one of the agents' answers — MV, OW, ISP, Dawid–Skene, all of them —
is capped by "at least one agent was right." Give KWA a candidate set wider than what the
ensemble produced and it isn't. Deliberately weak ensemble:

```
  ceiling for any vote-based method            89.7%

  MV-cluster                                   55.7%
  KWA, restricted to produced answers          76.0%
  KWA, wider candidate set                     80.4%

  on questions where EVERY agent was wrong:
    KWA restricted to produced answers          0.0%   (0 by construction)
    KWA with a wider candidate set             34.1%   <-- ceiling broken
```

**34% recovery on questions the entire ensemble got wrong.** This is the result I'd chase
first. It has no analogue in the multiple-choice setting, where the truth is on the ballot
by construction.

Big caveat: the wider candidate set is oracle-supplied here. In practice you'd need a
candidate generator (retrieval, or a model asked to propose alternatives), and its quality
becomes the binding constraint. Untested.

## 6. Robustness  (E6, E7)

**Nearer distractors → bigger advantage.** Exactly where the problem is hardest:

| similarity of wrong answers to truth | 0.40 | 0.55 | 0.70 | 0.85 |
|---|---|---|---|---|
| MV-exact | 93.4 | 90.3 | 83.5 | 68.2 |
| MV-cluster | 98.1 | 96.6 | 93.7 | 83.4 |
| KWA-EM | 99.1 | 98.6 | 96.9 | 89.9 |
| KWA − MV-exact | +5.7 | +8.3 | +13.4 | **+21.7** |

**Kernel misspecification is survivable.** True log-prob ∝ β·sim^c while we always fit c=1:

| curvature c | 0.5 | 1.0 | 1.5 | 2.0 |
|---|---|---|---|---|
| MV-cluster | 79.9 | 91.0 | 95.1 | 97.0 |
| KWA-EM | 89.0 | 95.5 | 97.7 | 98.7 |

KWA leads at every curvature, including where the model is wrong.

**Correlated agents hurt everyone, KWA least.** Two "families" pulled toward a shared wrong
answer (violates conditional independence):

| shared-error strength | 0.0 | 1.0 | 2.0 | 3.0 | **drop** |
|---|---|---|---|---|---|
| MV-exact | 79.6 | 77.5 | 72.0 | 60.0 | −19.6 |
| MV-cluster | 91.4 | 89.9 | 84.5 | 73.3 | −18.1 |
| OW-L | 85.1 | 84.1 | 77.5 | 55.8 | **−29.3** |
| KWA-EM | 96.0 | 95.2 | 92.0 | 83.2 | **−12.8** |

OW-L collapses hardest — consistent with agreement-based accuracy estimation being fooled
when colluding agents agree for the wrong reason. KWA is the most robust of the four.

**Support-selection bias** (E3): normalising over observed answers shrinks β by roughly 3×
but preserves ordering (corr 0.95 at N=5, 0.99 at N=12), and improves monotonically with
ensemble size. Since the aggregator needs only relative weights, the damage is small.

## 7. What is wrong with all of this

1. **100% synthetic.** The generative process and the fitted model are the same family
   everywhere except E7. This tests whether the estimator and aggregator *work*, not whether
   the model *is true of LLMs*. Nothing here is evidence about real systems.
2. **`sim` is a clean geometric object.** Real embedding similarity is non-metric, anisotropic,
   and its failure modes correlate with the models being aggregated. Untested.
3. **The 0.95 correctness threshold does a lot of work.** It defines what counts as a
   paraphrase versus a wrong answer, and every headline number moves with it.
4. **Fixed pool size C=10.** Real K_eff varies per question and correlates with difficulty.
5. **E9's candidate set is oracle-supplied.** The headline triangulation result depends on a
   generator that doesn't exist yet.
6. **No baseline from the confidence-weighting literature** (CISC, inverse-entropy voting).
   That's the incumbent KWA actually has to beat on real tasks, and it isn't here.

---

## 8. What I'd do next, in order

1. **Validate the model assumption on real data.** Take any multi-model QA set with free-form
   answers, embed, plot observed log-frequency against similarity-to-truth. If that isn't
   roughly linear, the whole formulation needs rethinking. This is cheap and it's the
   make-or-break test.
2. **Chase the triangulation result.** Build a real candidate generator and see whether the
   34% survives contact with reality. If it does, it's the paper — "aggregation that can
   output what no member said" is a genuinely new capability.
3. **Add the confidence-weighting baselines.** KWA has to beat CISC and inverse-entropy
   voting, not just majority voting.
4. **Fix the strong-agent identifiability.** Either a prior on β, or pool multiple samples per
   agent (self-consistency inside each agent) to sharpen the likelihood at the top end.
5. **Diversity-aware extension.** E7(b) shows correlated agents are the main threat.
   Down-weight agreement between similar agents — a covariance term on top of β.
