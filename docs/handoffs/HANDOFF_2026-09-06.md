## 2. The direction, restated

Not "a universal aggregation method." That framing competes with LLM synthesis
on generality and loses. The durable claim is narrower:

> **A generation carries evidence about its own reliability that the text does
> not**, and a synthesizer can only use what reached the page.

Aggregation is the setting where we demonstrate it, not the contribution.

### The system this implies

A synthesizer merging open-ended answers does three jobs. A single LLM pass does
all three implicitly and is only good at the third.

```
responses → decompose into claims → extract generation record
          → score each claim (calibrated p) → hand claims + p to an LLM → compose
```

Against plain LLM synthesis: implicit, salience-driven scoring is replaced by a
fitted scorer reading signals the concatenated text does not carry.
Against the current pipeline: the keep-budget disappears, so the output is not
forced to be a list — which is exactly what broke ASQA, where `DR*` is
length-dominated and a keep-count assumes an F1-shaped metric.

### Experiment ordering — product first

1. **baseline** — LLM synthesis, responses only. What everyone does today.
2. **+ calibrated p per claim** — the system. The number that matters.
3. **+ scrambled p** — control. Proves the gain is the probabilities, not format.
4. **+ raw features instead of p** — separate question: can the LLM infer the
   signals itself? If yes, you get accuracy *and* zero-shot generality.

Arm 3 is not optional. Arm 2 − arm 1 conflates evidence, extra tokens, and the
instruction to attend to a table. Arm 3 holds the last two fixed.

**It now fails loudly.** A failed call is never scored as an empty prediction; a

after 5 consecutive failures; a run under 90% complete prints a PARTIAL RUN
banner and sets `complete: false`.

### Two confounds still unfixed in the harness

- **Assistant order is fixed** (sorted by model name on every question). With
  known input-position bias — `guo2024serial`, our own citation — one agent is
  systematically advantaged. Randomise per question.
- **Candidate order in the evidence table is alphabetical.** Same problem.
  Randomise, using the same permutation across arms 2 and 3.

## 5. Findings from this session

### Reasoning traces were never persisted

Every generation file stores only `resp`. `backends/azure.py:167` reads
`reasoning_content` / `thinking` / `reasoning` **only as a fallback** when
`content` is empty and `finish_reason == "stop"` — so whenever a reasoning model
answered normally, its trace was discarded at the API boundary. Scanning 3,000
rows found 5 `</think` markers in QAMPARI, 3 in QUEST: the fallback cases, not
systematic traces. Reasoning **token counts** are computed (`rt`) for spend
accounting but not written into rows either.

Consequence: *considered-and-dropped vs never-considered* — the sharpest version
of graded omission, and the signal no prior work has — **requires regeneration**.
The code change is small (persist the field instead of only falling back to it,
and write `meta["reasoning"]` per row). Models that expose it: MAI-Thinking-1 and
grok-4.3 on Azure; o4-mini and qwen3-max-thinking in the `full_run` pool.

### We have far more cached data than the paper uses

| File | Content | In paper |
|---|---|---|
| `qampari_gen`, `cwq_gen`, `webqsp_gen`, `asqa_gen` | 4 open-ended benchmarks | 3 of 4 |
| `quest_gen` | QUEST, 400q × **8 agents** | no |
| `facts_gen` + `facts_judged` | FACTS Grounding, 300q × 5, already judged | no |
| `full_run` | TriviaQA, GSM8K, MedQA, MMLU-Pro ×6 — 750q × **10 agents** | no |
| `v2` | the same 9 domains, 996q × **7 different agents** | no |

`full_run` and `v2` are the same nine tasks through **disjoint agent pools**.
That is the "different group of agents" axis, already generated. The closed-ended
sets matter too: a framework that correctly says *"just use majority voting here"*
is more credible than one that always recommends itself.

Audit these four for gold completeness before counting on them.

### Why the method is scoped: the parameterisation

Roughly **81 of 92 features are indexed by agent identity** (`tab:blocks`):
`rankbuckets` is 56 = 8 agents × 7 bands, `base` has one indicator per agent,
`rank` and `omit` each carry a per-agent slot, `stack` is a lookup over 2^8
support patterns. Only ~11 are pool-invariant.

The scorer is literally parameterised by those eight specific models. Swap the
pool and it is undefined. MAS-Orchestra generalises because it abstracts
sub-agents as callable functions; we do the opposite.

To transfer: `rankbuckets` → rank percentile within the asserter's own output;
per-agent indicators → that agent's measured solo precision; `stack` → a function
of `|S(c)|/n` and pool aggregate reliability. Expect an in-distribution cost —
that trade should be deliberate, not a surprise when the number drops.

### Prior-art check

Closest neighbours all feed the fusion step the same *kind* of thing: a scalar
reliability estimate. [UAF](https://arxiv.org/html/2503.05757) uses perplexity,
semantic entropy and internal-state probing, combined **by formula not prompting**,
and states outright these "do not rely on generation process properties like
response length, position of content, or omissions."
[Roundtable Policy](https://arxiv.org/abs/2509.16839) has a Fusion Agent guided
by a confidence weight table. AdaFuse and factor-graph ensembling fuse at the
logit layer — white-box only.

Two gaps, and the second is ours:

- **Granularity.** Every one of those signals is *per-response*. Perplexity over a
  100-item list says nothing about which item is wrong.
- **Kind.** Theirs estimate *how sure the model is*. Ours are observables about
  *how it produced the output*.

Also: UAF needs logprobs or internal states. Our pool is proprietary API models,
several exposing nothing — our signals work black-box where perplexity-based
methods cannot run at all.

**Unresolved:** Roundtable Policy's PDF did not extract cleanly; only the abstract
was read. Someone should check whether its Fusion Agent gets anything beyond an
accuracy table, and whether its tasks are open-ended or short-answer. If it does
per-claim evidence on open-ended tasks, positioning changes.

## 6. Open questions, ranked

1. **Does the scorer transfer across pools?** The hinge. LOSO shows transfer
   across *question types within QAMPARI with the same eight agents* — not the
   same thing. The 210-subset sweep does not test it either: those are subsets of
   the same eight, feature vector still 8-shaped with columns zeroed. Cached data,
   days of work. A negative answer redirects everything.
2. **Does plain LLM synthesis beat aggregation outright?** Blocked on credits.
   Currently the paper cites `chen2023universal` and `jiang2023llm` in related
   work and runs neither as a baseline. First question any reviewer asks.
3. **Does a selector beat exhaustive cross-validation of all ~60 rules?** If not,
   the framework is decoration over a worse method. It must win on sample
   efficiency or interpretability, not accuracy.
4. **Does the gain shrink as agents get stronger?** MAS-Orchestra reports gains
   diminishing with stronger sub-agents. Our 210 subsets span best-single
   24.72 → 27.18 with gain over counting +4.43 → +2.31. Same curve? Testable on
   cached data, and it tells us how much runway the direction has.
