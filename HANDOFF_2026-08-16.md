## 2. Findings, sorted by how much they survived

### Solid — mechanism understood, measured more than once

**Grading granularity dominates method effects.** Identical 214-word responses, identical
models, only the judge's granularity changed:

```
  binary response-level    unanimous 80.0%   best single 97.1%   headroom  2.9 pts
  sentence-level           unanimous 30.3%   best single 75.8%   headroom 21.2 pts
```

Independently corroborated by arXiv 2504.18413 ("An Empirical Study of Evaluating
Long-form QA"): style/length/category bias automatic metrics, and *fine-grained
evaluation mitigates it*. **Every benchmark rejected during the search was judged
binary — some were probably fine.**

**A one-sided metric makes a degenerate strategy optimal.** On ASQA, STR-EM has no
precision penalty. Pasting all five responses together — no method at all — produces
4.9× more text (393 words vs 81) and scores **58.48%**, beating every method. Measured
against that baseline all filters *lose*. The tell: ASC's optimal threshold was Θ=1,
i.e. "filter nothing". **When the optimal setting of a filter is not to filter, the
metric is rewarding something other than the method.**

**The label-free estimator needs similarity SPREAD, which long answers destroy.**

```
  v2 short answers    mean sim 0.889   sd 0.200   -> EM works, picks spread across models
  FACTS long answers  mean sim 0.876   sd 0.105   -> EM collapses
```

Means are nearly identical; the spread halves. On FACTS, EM returned
`beta = [0.01, 8.61, 0.01, 0.01, 0.01]` and the "aggregator" output **Kimi's answer
259/259 times (100%)** — its 91.78% score *is* Kimi's solo score. On ASQA, Spearman
vs true accuracy was **+0.000**. The kernel needs long answers; the estimator needs
short ones. They require opposite conditions.

**Measurement artifacts exceed the effects being measured.** All from this project:

| artifact | size |
|---|---|
| in-sample weight fitting | 1.86 pts |
| uncalibrated interaction null | 2.46 pts |
| answer normalisation (one vendor's control token) | 1.13 pts |
| two good-faith implementations of the same table | 0.93 pts |
| judge self-contradiction on identical answers | 7% |
| sign flips with sample size | 3 occurrences |

Published gains in this literature are 1–3 points.

### Dead

- **KWA beats its ingredients.** Refuted on TriviaQA, then on v2, then on FACTS.
- **Bayes-optimality.** `agg_kernel` drops the `logZ` term `_agent_logp` computes. I
  implemented the correct normalised rule and tested it: **worse** (−3.61 label-free on
  v2, CI excludes zero; +0.45 on FACTS, spans zero). It is an energy-based heuristic.
- **Per-question / per-domain weights.** Per-domain β scored *below* global β.
- **Fact-level weights (the last hypothesis).** ASQA −0.90 [−1.60, −0.31]; QAMPARI
  −0.20 [−0.93, +0.41].

### Unresolved — do not quote a direction

Every ranking among aggregators. They flip with n, with implementation, with metric.
Specific reversals observed: medoid (n=36 → n=259), weighted filter (n=141 → n=198),
label-free KWA (implementation A → B).

## 5. Traps — every one of these cost real time

1. **Empty responses written as rows.** `resp=""` grades as incorrect and is
   indistinguishable from a wrong answer. Caused a fake 67-point capability spread.
   Fixed: `if txt:` not `if txt is not None`.
2. **Judge graded everything INCORRECT** — 0 of 6,606 — because `max_tokens=5` on a
   thinking model returns `content: null`, and `("").startswith("CORRECT")` is `False`.
   **Any judge swap must re-check the token budget.**
3. **Permutation test could never reject.** It permuted rows then took a column mean,
   which is invariant to row order. `p` was pinned at 1.0000 by construction.
4. **`analyze_domains.aggregation()` does not run the method.** It compares by exact
   string identity of the last 120 chars and never imports `kernel_agg`. 94.8% of
   answers are distinct, so its "majority vote" is a random pick and its "weighted vote"
   just selects the top-weighted model. It measures *selection*, not aggregation.
5. **`agg_majority_exact` with `ans = arange(N)`** gives every answer its own candidate
   index → always an N-way tie → random. Identical answers must share an index.
6. **Reasoning tokens are billed but sit OUTSIDE `completion_tokens`.** Measured on
   grok-4.3: `total=207, prompt=21, completion=26, reasoning=160`. Use
   `total_tokens − prompt_tokens`.
7. **Azure prices mix per-1K and per-1M units in the same API.** Read `unitOfMeasure`.
8. **Deploymentless inference is not capacity you own.** gpt-5.x answered, then failed
   `deployment_disabled` once other models were deployed, then worked again. Fine for a
   judge (resumable); never put it in the pool.
9. **`logit(accuracy)` goes negative when accuracy < 50%.** On QAMPARI every model's
   precision is 8–35%, so a Σβ threshold filter returned the **empty set at every
   theta**. For set tasks use a non-negative weight (precision works).
10. **The judge sees the whole response, not the final answer.** It contradicted itself
    on **7% of identical answers** in the v2 run.

## 7. What to do next

**Do not run another benchmark to rescue the method.** Four have now said the same
thing, and a fifth costs money to reach the same place.

1. **Write the measurement paper.** The evidence is in §2 and it is unusually strong:
   six quantified artifacts, two externally corroborated, all from one project.
2. **The ensemble-subset sweep** — 16 subsets from the 5-model pools, 99 from the
   7-model v2 pool. No new API calls. Converts every unstable single-ensemble ranking
   into a trend, which is the only route to credibility for ~1-point effects.
3. **Same-family vs cross-family error correlation.** The v2 pool is one model per lab,
   so this is free and separates lineage from shared item difficulty — a confound the
   ChatGPT review correctly flagged in the 215–621× claim.
4. **If continuing the method at all:** ASQA needs ROUGE alongside STR-EM so padding is
   penalised, and Θ must be cross-fit rather than swept on the evaluation set.

## 8. What to distrust, including in this document

Three measurement bugs in one session, **all favouring the method** — supervised weights
instead of EM, a random-tie baseline, and missing deduplication. None favoured the null.
That is the signature of scrutinising the interesting number and taking the boring ones
on faith.

Before anything goes external, re-derive one headline number independently from
`data/v2.jsonl` without reading the analysis scripts first. If majority vote lands near
82.99% and label-free KWA near 82.58%, the numbers hold.

Specifically unverified: `verify_aggregation.py`'s normaliser uses `B.norm()`, which
strips articles and punctuation aggressively. It has **not** been checked that it never
merges two genuinely different answers. If it does, majority vote is overstated.
